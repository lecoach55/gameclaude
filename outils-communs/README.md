# Outils communs à tous les jeux

À réutiliser dans chaque jeu de Victor (Valdragon, Hameau, Président de Club, etc.).

- **`testkit.js`** — à intégrer dans le jeu : bouton 🐞 « signaler un problème » (capture, état, erreurs), compteur d'images par seconde, banc de mesure scripté. Pour un jeu en scripts classiques (sans `import`), charger `<script type="module" src="testkit.js">` : la trousse est aussi exposée sur `window.Testkit` (exemple : `sedes-petri`). Pour un jeu 2D, le GPU est lu sur un canvas WebGL temporaire. Les résultats vont dans la base de l'artefact : Claude les lit avec `db_list` sur la collection `data/users/<id>` (documents `mesures_*` et `signalement_*`). **v7 (17/11)** : sur un appareil où toutes les images dépassent 1 s (rendu logiciel, Mac Intel en Haute), elles comptent (pause = image > 1 s **et** > 8× la médiane) et la mesure porte `lent:true` ; avant, le banc rendait une scène vide (`fps` absent) marquée « masquée » à tort. `masquee` reste pour une page cachée ou qui n'affiche presque rien (< 3 images, pause, images < 60 % de la durée) : sur un appareil à plus de 1,7 s par image, lire `n` et `pire`.
- **`maj_testkit.py`** — **versions de la trousse** : `python3 outils-communs/maj_testkit.py` dit pour chaque jeu la version de sa copie de `testkit.js` (fichier à part, bloc `/*TESTKIT-DEBUT*/ … /*TESTKIT-FIN*/`, trousse recopiée dans le code, page construite) et **ce qui lui manque** (filtre des pauses, attente de la base, secours…) ; `… <jeu> --appliquer` remplace les copies remplaçables en gardant le style (avec ou sans `export`), refuse s'il y a des ajouts locaux ou des modifications non commitées (`--forcer` pour passer outre), ne touche jamais une trousse intégrée sans repères (il donne ses lignes : les entourer une fois des deux repères). La trousse porte son numéro (`TK.version`, champ `tk` dans chaque `mesures_*` / `signalement_*`) ; **à chaque changement de `testkit.js`, augmenter le numéro et ajouter une ligne à `VERSIONS`** (le contrôle de `verifier_outils.py` le rappelle). `bureau.py` s'en sert pour l'alerte « testkit périmé ».
- **`banc.py`** — **banc commun de fluidité** (remplace les `perf.py` recopiés) : `python3 outils-communs/banc.py <jeu>/outils/banc.json [sortie.json]` ; **avant/après dans la même minute** : `… --avant HEAD` (révision git extraite et construite à part, mesures entrelacées A B B A ; `--avant-dossier` / `--avant-page` pour une autre copie), tableau des écarts avec le **bruit mesuré**, `--strict` = code 1 si une scène ralentit au-delà du seuil (10 %) et du bruit ; `--comparer a.json b.json`. Par défaut le temps est **figé** (`horloge.js`) : le banc joue lui-même chaque image et attend le GPU (lecture d'1 pixel des canvas affichés) → **coût réel d'une image**, même état d'une passe à l'autre, sans plafond à 60 img/s (l'ancien banc voyait « 60 img/s » partout chez Trône de Braise à CPU ×1 : un ralentissement de +45 % était invisible). Réglages en JSON (scènes = JS pour s'y placer, `infos` pour appels/triangles, `chronos` pour chronométrer une fonction ; toutes les clés en tête de `banc.py`) ; `"preparation": "reelle"` pour un jeu qui découpe son chargement selon `performance.now` (Bannières). Exemples : `trone-de-braise/outils/banc.json`, `bannieres/outils/banc.json`, `hameau/outils/banc.json`. **Un seul banc à la fois par machine** (deux bancs ensemble faussaient les ms : charge 5 à 12 sur 2 cœurs) : le second attend en le disant (`--attente-max 1800`, `--sans-verrou`) ; **mesures écrites au fil des scènes** dans `<sortie>.partiel.json` (ou `/tmp/banc-<jeu>.partiel.json`) avec le temps restant estimé, aussi affiché à l'écran (`[3/12, reste ≈ 6 min]`) ; la sortie note la charge de la machine. **Depuis le 17/11 (soir)** : `--avant HEAD` extrait **tout le dépôt** (≈ 2 s ; le donjon 3D du Trône, qui lit `valdragon/jeu`, se construit) et ne laisse plus une construction à chemin absolu (`/home/claude/banc/…` : Cage & Gloire, Hameau, Wall Street) écraser l'APRÈS (avant : avant = après, aucune alerte possible) ; `--avant-dossier` accepte la **racine d'un worktree** (on y sert le même chemin ; avant : 404 puis « jamais prêt » 180 s par passe, 21 min perdues) ; page absente = arrêt immédiat (code 2) ; version jamais prête 2 fois = plus relancée (`"pret_max_s"`). **Gels** (`"gels": [{"nom", "stockage", "avant", "js", "duree_ms", "occupe"}]`) : le **gel au changement** (qualité, étage, entrée en combat) mesuré en temps réel sur page neuve — pire image en jeu, régime, préparation annoncée exclue, **programmes WebGL compilés en jeu** (compteur `linkProgram`, tout moteur ; doit être 0) ; avant/après : « plus lent » si ces programmes augmentent à chaque tour. `--gels tous` (eux seuls), `--sans-gels`. **Chronos (18/11)** : « plus lent » seulement au-delà de 2×seuil, du bruit entre passes (plafonné à 4×seuil) et de 0,3 ms, dans le même sens à chaque tour (avant : C&L `tour_ms` 0,65 → 1,15 ms « plus lent +77 % » sur un code identique ; 4 bancs après : 0 fausse alerte). Remplace les `gel.py` / `gel3d.py` propres à Valdragon et au Trône. **Scènes « action » (18/11, jeux DOM/SVG qui redessinent sur un clic : leurs scènes lisaient 0,00 ms/img et seuls les chronos JS comptaient)** : `{"nom": "zoom_engage", "js": "…placement…", "action": "applyVB(true)"}` = coût d'une action **jusqu'à l'affichage** (JS + styles + mise en page + peinture + **dessin hors fil principal**, trajet vide déduit, 12 répétitions) avec le détail `js_ms` / `principal_ms` / `raster_ms` ; action asynchrone : `()=>promesse` (`attente_ms`), `"delai_s"` ; « plus lent » au-delà de 2×seuil, viser `--tours 3`. Couronnes & Complots : `render()` 5 ms de JS mais 14-25 ms jusqu'à l'affichage, **zoom engagé 100-380 ms** (invisible jusqu'ici) ; un SVG 2× plus lourd à dessiner : +66 à +121 % vus (le chrono JS : rien). `banc.py -h` (et `captures.py`, `verif.py`) affiche l'aide ; dossier d'une page à chemin absolu créé d'office avant la construction.
- **`--avant arrivee`** (18/11 soir ; `banc.py`, `captures.py`, `verif.py` et `"avant": "arrivee"` dans `verif.json`) — compare au **début du chantier en cours** (le commit de `bureau.py arrivee <jeu>`) au lieu du dernier commit : les commits faits en route restent dans l'APRÈS (retour Cage & Gloire : avec `HEAD`, fausses alertes et ralentissement commité plus tôt invisible). Sans chantier ouvert ou arrivée non commitée = HEAD (dit) ; chantier ré-ouvert = nouvelle base ; clone superficiel trop court = HEAD avec avertissement ; `--avant HEAD` avertit si des commits du chantier touchent déjà le jeu. Essai : ralentissement commité en route, `HEAD` → « égal (bruit) », `arrivee` → **+183 % / +231 % « plus lent »**.
- **`verrou.py`** (18/11) — **verrou machine commun : les bancs passent SEULS, les robots ENSEMBLE mais jamais pendant un banc** (retours Hameau et Une vie : captures et robots des agents pendant un banc = bruit 69-315 %, mesures inexploitables). `banc.py` prend le verrou exclusif (comme avant), `captures.py`, `robots/singe.py` et chaque **commande du jeu dans `verif.py`** prennent le verrou partagé ; **file d'attente** : dès qu'un banc attend, les nouveaux robots passent derrière lui (pas de famine). Qui tient la machine est dit chaque minute (`python3 outils-communs/verrou.py etat`). Pour un outil propre à un jeu, sans toucher à son code : `python3 outils-communs/verrou.py robot -- python3 <jeu>/outils/explore.py …` (ou `banc -- … perf.py` pour un banc à soi) ; dans `verif.json` : `"verrou": "banc"` pour une commande qui mesure, `false` pour aucun. Options `--sans-verrou`, `--attente-max 1800` (captures, singe, banc) ; `VERROU_AUCUN=1`. Mesure (Trône de Braise ×3 tours, singe C&L 30 s en même temps) : seul → bruit 8-12 % ; singe sans verrou → ms +10-20 %, bruit 20-28 % ; avec verrou → le singe attend 36 s, bruit 10-14 %, ms comme seul. **Navigateurs hors verrou (18/11 soir, retour Bannières « machine libre » annoncée pendant que d'autres Chromium tournaient)** : `verrou.py` lit aussi les processus ; tout Chromium dont le lanceur ne prend pas le verrou (robot d'un jeu lancé tel quel) est listé par `etat` avec son lanceur et son % de processeur (ACTIF / calme / **ORPHELIN** = lanceur disparu, à arrêter avec `kill`) ; un banc attend la fin des navigateurs actifs AVANT de prendre la file (au plus `--attente-navigateurs 600`, `0` = ne pas attendre ; `VERROU_NAVIGATEURS`), puis note ceux encore actifs au début ou à la fin dans sa sortie (`navigateurs_hors_verrou`, réserve dans le rapport de `verif.py`). Mesure (banc Trône 2 tours, page occupée hors verrou) : avant = mesure immédiate, ms +12 à +20 %, bruit 11-25 %, pire image 116 ms, rien de signalé ; après = le banc attend 42 s, ms comme seul (9,3-9,9), bruit 13-14 %.
- **`--avant` et pages à chemin absolu** (18/11, `banc.py` et `captures.py`) : un dossier **partagé** (`/home/claude/cg.html`, `/home/claude/banc/` qui sert trois jeux) n'est plus recopié en entier (avant : tout `/home/claude`, dépôt compris, puis `shutil.Error` en le remettant) : seuls la page et les `"sorties"` des réglages sont mis de côté et remis, rien d'autre n'est touché (un voisin changé pendant la construction est signalé) ; un dossier **propre à la page** (aucune autre `.html`) est suivi en entier, fichiers **supprimés** compris, remise en place même si la construction échoue. Page absente avec `"construire"` → **construite d'office** (avant : « page APRÈS introuvable »).
- **`profil3d.py`** (18/11) — **ce qui coûte dans une image 3D**, pour tout jeu Three.js, **sans rien exposer dans le jeu** : `python3 outils-communs/profil3d.py <jeu>/outils/banc.json [sortie.json] --scenes carte` (= `banc.py … --profil`). Reprend les scènes du banc (même page, temps figé, GPU attendu), trouve moteurs et scènes par le crochet `__THREE_DEVTOOLS__` de three.js, puis masque tour à tour chaque **groupe d'objets** (enfants de la scène regroupés par nom ; un groupe qui porte plus de la moitié des triangles ou des objets est ouvert) et essaie **sans ombres / sans environnement / sans lumières ponctuelles / sans brouillard / résolution ½** ; tableau trié « gain en ms et %, appels et triangles en moins », base remesurée toutes les 4 variantes (**bruit affiché** : ◀ = poste notable ≥ 2× le bruit). Seules les images vraiment dessinées comptent (jeu qui redessine une image sur deux). Objet remis visible par le jeu à chaque image = signalé. Tout est remis en place après chaque variante. Réglages facultatifs : `"profil": {"groupes": 20, "images": 0, "scene": "expression d'une THREE.Scene"}`. Remplace `bannieres/outils/prof3d.py` et `valdragon/outils/mesure/bprof.py`.
- **`routes.py`** — **bibliothèques du CDN servies en local** : une page qui charge Three.js sur `cdn.jsdelivr.net` ou `unpkg.com` (bloqués dans le bac à sable : Hameau restait sur un écran noir, `__cam is not defined`) le reçoit d'une copie locale de la même version (`$THREE`, `/home/claude/t3d`, `/home/claude/deps`, sinon `npm pack three@<v>` une fois dans `~/.cache/gameclaude`, ≈ 1 s). Actif par défaut dans `atelier.page()`, `banc.py` et `robots/singe.py` ; réglage `"routes": {"https://adresse/": "dossier/local/" | "" (vide) | null (refus)}` pour d'autres adresses, `false` pour couper. Script Playwright à soi : `from routes import brancher_sync; brancher_sync(pg)` (async : `await brancher(pg)`), journal `{servis, manquants}`. Essai : `python3 outils-communs/routes.py essai page.html`. Jamais de fichier hors du dossier routé (`..`, `//`) ; une version introuvable = fichier « manquant », l'outil continue.
- **`atelier.py`** — fonctions Python communes : serveur local (**`base = serveur(dossier, port)` : toujours utiliser l'adresse renvoyée** ; depuis le 17/11 il ne réutilise un serveur ouvert que s'il sert CE dossier — avant, la copie « avant » et la copie « après » pouvaient être servies par le même serveur sans qu'on le voie ; sinon port suivant, annoncé sur stderr ; démarrage ≈ 0,1 s au lieu d'1 s ; un serveur dont le dossier a été effacé est remplacé ; ceux d'un dossier sous /tmp s'arrêtent à la fin du script, `fermer()` pour les autres), page neuve (localStorage préparé, temps accéléré ; **`tactile=True`** : vrai téléphone, `has_touch`/`is_mobile`, `pg.touchscreen.tap` ; Three.js du CDN servi en local, `routes=`), mesure des images (`mesurer` : mêmes clés que les `mesures_*` de `testkit.js` — `fps`, `bas1` = img/s du 1 % le plus lent, `pire`, `n`, `pauses` > 1 s et > 8× la médiane écartées, `lent` — plus `ms`, `med`, `p95` ; `navigateur(p, plafond=False)` : images non plafonnées à 60/s), captures.
- **`sauvegarde-en-ligne.js`** — sauvegarde dans la base de l'artefact pour les grosses parties (gzip + découpage en morceaux), avec reprise proposée quand un autre appareil a une partie plus récente. Utilisée par Wall Street.
- **`captures.py`** — **studio de captures commun** (18/11, remplace les `captures.py` / `studio.py` / `capt.py` / `refs.py` recopiés) : `python3 outils-communs/captures.py <jeu>/outils/vues.json [sortie] [--comparer <jeu>/references] [--strict]`. Vues en JSON (mêmes clés de chargement que `banc.json` : `fichier`/`dossier`, `construire`, `stockage`, `pret`, `entree`, `preparation`, `routes`, `appareils` avec `dpr`, `tactile`, `mouvement_reduit` ; puis `"vues": [{"nom","js","attendre","occupe","images","pas","seule","clip","infos"}]`). **Temps figé** par défaut (horloge.js : deux séries identiques au pixel), **`occupe`** = le jeu prépare (shaders, chargement) : l'outil joue des images jusqu'à ce que ce soit fini, avant ET après les images de la vue (au lieu de délais fixes trop courts), 🐞 et voyant 🧪 cachés, animations CSS figées. **`--avant HEAD`** (ou `--avant-dossier`, `--avant-page`, comme le banc) : capture la révision et la version en cours puis les compare → **plus besoin de références dans le dépôt** ; **références légères** `--format jpg --echelle 0.5` (C&L 3D : 15 Mo → 0,9 Mo, 0 fausse alerte contre les PNG pleine taille) ; **`--stabilite`** : chaque vue capturée deux fois, une vue qui change d'une série à l'autre est signalée (fausse alerte assurée) ; `--vues`, `--appareils`, `--strict` (alerte, image manquante, vue en échec, erreur JS, vue instable). Sortie : images, `captures.json` (durée, images jouées, erreurs, `infos`), `planche.png` + `comparaison.json`. Seules les images que la série refait sont remplacées dans la sortie. Exemple : `couronnes-et-lignees/outils/vues.json` (2D) et `vues3d.json`.
- **`compare.py`** — comparaison d'images référence / nouvelle version, tolérante aux petits décalages de caméra. Signale les changements visuels involontaires. `python3 compare.py refs/ nouvelles/ planche.png [seuil] [--json r.json] [--strict]` : `--json` écrit le résultat par scène, `--strict` rend le code 1 s'il y a une alerte ou une image manquante (pour `verif` et les scripts ; sans lui le code reste 0). **18/11** : images `.png`, `.jpg`, `.webp` appariées par nom (une référence JPEG réduite se compare à une capture PNG ; `.png` prioritaire en cas de doublon) ; les planches (`planche*.png`) ne sont plus comptées comme vues manquantes (C&L `--strict` : code 1 sans aucune alerte → 0).
- **`horloge.js`** — captures **reproductibles** : injecté avant le jeu, il fige le temps (`performance.now`, `Date`) et met `Math.random` sur une graine ; les images ne tournent plus qu'à la demande (`__horloge.avancer(n, pas_ms)`). Deux séries de captures faites à des moments différents, sur une machine plus ou moins lente, sont identiques : plus de fausses alertes de `compare.py` dues à une caméra qui oscille ou à des particules. Dans un script Playwright existant, une ligne avant `goto` : `await pg.add_init_script(path='…/outils-communs/horloge.js')`, puis avant chaque capture `await pg.evaluate('__horloge.avancer(16,162)')` (≈ 2,6 s de jeu en 16 images : rapide en SwiftShader ; prendre plus d'images de 16,7 ms si le jeu plafonne son pas de temps et que l'animation doit aller au bout). Avec `atelier.py` : `pg = await page(nav, url, figer=12345)` puis `await avancer(pg, 16, 162)`. `__horloge.auto(true)` relance le temps virtuel image par image (écran d'accueil animé), `auto(false)` refige. `__horloge.reel(true)` : temps et images réels (hasard toujours à graine) le temps d'un chargement, `reel(false)` refige (`window.__HORLOGE_REEL=1` avant l'injection : démarrage en temps réel) ; `__horloge.coulant(true)` : le temps avance pour de vrai **entre** deux images (images toujours à t+pas) — un travail découpé « tant que `performance.now()-t0 < 8` » ne boucle plus sans fin. Avec l'horloge figée, `page.wait_for_function` attend des images qui ne viennent pas : passer `polling=100` ou utiliser `atelier.attendre(pg, 'condition JS')` (joue des images jusqu'à ce que la condition soit vraie). Les erreurs dans les images restent visibles (`pageerror`). Ne pas mesurer les img/s avec l'horloge figée ; une boucle d'attente active sur `performance.now()` ne voit plus le temps passer ; une boucle de jeu sur `setInterval` n'est pas figée. Les références doivent être refaites une fois avec l'horloge (le cadrage n'est plus celui du hasard).

- **`sonde.py`** (+ `sonde.js`) — aides pour **tous les robots Playwright** (synchrones ou async, page figée ou non) :
  - `cliquer(pg, 'Naître')` (`await` en async) attend jusqu'à 10 s qu'un bouton **visible, actif et non recouvert** contienne ce texte (casse et espaces ignorés, ou `re.compile(…)`), puis le clique (marche aussi sur un `<g>` SVG) ; `dans='#go'` limite au conteneur, `sel='tr[data-t]'` change les éléments visés ; `souris=True` fait un vrai clic au doigt/souris (pour un jeu qui n'écoute que `pointerdown`/`touchstart`). Page figée par `horloge.js` : l'attente ne joue qu'une image par 100 ms réelles, les captures suivantes restent reproductibles. S'il n'apparaît pas : `TimeoutError` qui **liste les boutons visibles**, au lieu de « Cannot read properties of undefined (reading 'click') ». Remplace les `evaluate("…find(b=>/X/.test(b.innerText)).click()")` (≈ 70 `.click()` lancés par `evaluate` dans 29 outils).
  - `debordements(pg, ignorer=['.tbl-wrap'])` liste les **contenus coupés** de l'écran affiché, pas seulement la largeur de la page : `page` (la page défile en largeur), `bloc` (un bloc qui défile seul — panneau, fiche — contient un élément trop large), `coupe` (du **texte** caché par `overflow:hidden` ; un décor qui dépasse ne compte pas), `bord` (élément à moitié sorti de l'écran, masqué par `body{overflow-x:hidden}`). Ignorés car voulus : tableau plus large que son bloc, rangée d'onglets, bandeau défilant, tiroir fermé, « … » (genre `large`, `ellipses=True` pour les voir). `resume(liste)` en une ligne. Exemple Wall Street : la fiche action coupée au téléphone (`bloc aside#aside +109 px` à 360 px) que le contrôle `scrollWidth` ne voyait pas.
  - `cliquer(pg, '+1 mois', effet='G.day')` vérifie en plus que le clic a **changé quelque chose** (valeur de l'expression, ou `effet=True` : texte affiché, cases, étiquettes aria, fenêtres ouvertes) ; sinon `ClicSansEffet` (bouton mort, ou clic avalé par une fenêtre — le « +1 mois » compté 21 fois de Wall Street alors que la séance ne bougeait pas). `__sonde.dessus()` dit ce qui est sous le doigt (voile invisible).
  - Dans un script sans import Python (Node, `wait_for_function`) : `pg.add_init_script(path='…/outils-communs/sonde.js')` puis `__sonde.cliquer('Jouer')`, `__sonde.debordements()`, `__sonde.boutons()`. Aussi exposés par `atelier.py`.
- **`robots/singe.py`** — **singe commun** (clics, tapotements, glissés, touches au hasard), téléphone **et** ordinateur en une commande : `python3 outils-communs/robots/singe.py <jeu>/outils/singe.json [--secondes 60] [--graine 1] [--appareils telephone,ordinateur] [--fichier page.html]`. Ne touche que des boutons visibles, actifs et **non recouverts** (fait défiler une fenêtre pour atteindre un bouton du bas), jamais 🐞 / 🧪 / banc ; refuse les confirmations « effacer / nouvelle partie ». Rapport à l'écran et dans `/tmp/singe-<jeu>/singe.json` : erreurs JS (avec les 5 dernières actions et une capture), blocages (plus rien de cliquable, écran figé), invariants du jeu, sorties du jeu, contenus coupés par écran (`debordements`), boutons jamais efficaces, progression (`etat` début → fin). Code 1 s'il y a une erreur, un blocage ou un invariant violé. Réglages en JSON (une quinzaine de lignes, toutes les clés sont décrites en tête de `singe.py`) : `fichier`/`dossier`, `entree`, `pret`, `eviter`, `selecteur`, `priorites`, `avancer`, `etat`, `invariants`, `relance`. Exemples : `sedes-petri/outils/singe.json`, `wallstreet/outils/singe.json`, `president-de-club/outils/singe.json`.
  - **Mode explorateur** `--couvrir` (ou `"couvrir": true`) : touche d'abord les boutons jamais touchés de l'écran affiché (+25 à +80 % de boutons distincts dans le même temps) ; réglage `"ecran"` = expression JS du nom d'écran (sinon fenêtre ouverte / premier titre). Dans les deux modes : contenus coupés relevés à la première apparition de chaque écran, **couverture** (boutons vus / touchés par écran, liste des jamais touchés) et **actions lentes** (> 0,4 s) dans le rapport ; `--actions N` arrête après N gestes (essais reproductibles). Exemple : `couronnes-et-lignees/outils/singe.json`.
  - **Jeux 3D lourds** : `--images 1` (ou `"images": 1`) = mode économe — temps figé entre les actions, une image jouée après chacune (avant, le jeu dessinait sans arrêt et chaque relevé attendait une image de 2,7 s) : Hameau 4 → 39 actions en 2×45 s. Three.js du CDN servi en local (`routes.py`). `--ordinateur 1280x800` / `--telephone 360x740` (ou réglages) pour le format d'écran. Exemple : `hameau/outils/singe.json`.
  - Les clics de `sonde` (`cibles`, `viser`, `cliquer`) visent le centre **entier de la partie visible** d'un bouton (coupé par l'écran ou une fenêtre qui défile, bordures exclues) : un bouton à moitié sous le bord d'une fenêtre est vraiment touché.

## Règle d'or
1. Rendre le jeu **reproductible** : une graine fixe (`Math.random` remplacé) et une fonction pour se placer dans une scène donnée.
2. Mesurer avant/après (banc), capturer et comparer aux références, tester avec un parcours automatique, puis publier.
3. Le mode test ne touche jamais à la vraie sauvegarde du joueur.

Exemple complet : `valdragon/outils` et le mode test de Valdragon (bouton 🧪 sur l'écran titre).


Adaptation pour un jeu sans canvas (DOM/SVG) : voir `couronnes-et-lignees/jeu/app.js` (Testkit intégré sans `export`, `etat()` qui envoie l'écran ouvert et la sauvegarde). Testeur au doigt générique pour ce genre de jeu : `couronnes-et-lignees/outils/tests/explore.py`.

## Pièges déjà rencontrés
- **`window.claude` peut arriver après le chargement** : une sauvegarde en ligne qui teste `window.claude` au démarrage et mémorise l'échec ne sauvegarde plus jamais (Sedes Petri : aucune partie ni mesure reçue). Attendre jusqu'à 10 s, ne mémoriser que le succès, afficher l'état (« ☁ Sauvegarde en ligne : active / refusée… ») dans le menu. `testkit.js` le fait désormais (raison dans `TK.base`, renvoyée avec le banc).
- Préférer une copie de `testkit.js` sans les mots `export` chargée en `<script src>` classique : plus sûr qu'un `<script type="module">` dans le cadre isolé de l'artefact.
- Sur téléphone, vérifier que le menu reste accessible : un sélecteur CSS mal orthographié (`.icon-btn` au lieu de `.iconbtn`) cachait le menu de Wall Street depuis le début.
- Le banc ne doit jamais toucher la vraie partie : copier l'état, couper la sauvegarde (locale ET en ligne), mesurer, puis tout remettre.
